# Серверный фреймворк — Spring Boot

## Контекст и постановка задачи

Серверная часть «Должок» должна реализовывать REST API, аутентификацию, работу с PostgreSQL, отправку почты и планировщик повторных отправок (REQ-SEC-001…005, REQ-NOT-001, REQ-NOT-002, REQ-SEC-002). Ограничение 2.3 SRS требует Java. Нужно выбрать фреймворк, который позволит уложиться в 12 недель с одним разработчиком и с junior на первых четырёх итерациях.

Вопрос: какой серверный фреймворк на Java выбрать, чтобы минимизировать собственную реализацию безопасности, почты и работы с БД?

## Драйверы решения

* Зрелая поддержка безопасности (сессии, bcrypt, защита от CSRF/XSS) — REQ-SEC-001, REQ-SEC-003, REQ-SEC-004.
* Готовые решения для почты и планировщика — REQ-NOT-001, REQ-NOT-002.
* Знакомство команды (студент, junior) с инструментом — срок 12 недель.
* Объём документации и примеров для junior-разработчика.

## Рассмотренные варианты

* Spring Boot 3
* Quarkus
* Java EE / Jakarta EE на сервере приложений (WildFly)

## Итог решения

Выбранный вариант: «Spring Boot 3», потому что он даёт готовые модули Spring Security (сессии, bcrypt, защита от CSRF), Spring Data JPA (работа с PostgreSQL и оптимистичные блокировки), Spring Mail (отправка почты), Spring Scheduling (очередь отправки). Подробная документация и большое число примеров снижают риск для junior-разработчика. Quarkus быстрее стартует, но для учебного проекта экономия ресурсов не даёт выигрыша, а знакомство команды с ним меньше. Jakarta EE требует настройки сервера приложений, что усложняет развёртывание в Docker (REQ-QUAL-006).

### Последствия

* Хорошо, потому что безопасность и почта реализуются конфигурацией, а не с нуля (REQ-SEC-001…004).
* Хорошо, потому что junior-разработчик быстрее найдёт примеры решений.
* Плохо, потому что Spring Boot запускается медленнее Quarkus; для требований производительности (REQ-PERF-001) это не критично, но учитываем при нагрузочном тесте (REQ-PERF-002).
* Плохо, потому что фреймворк накладывает свои соглашения о структуре пакетов, что нужно зафиксировать в SDD (DES-002).

### Подтверждение

* Архитектурный тест (ArchUnit) проверяет, что контроллеры не обращаются к репозиториям напрямую.
* Ревью кода Исполнителем каждую итерацию.

## Плюсы и минусы вариантов

### Spring Boot 3

* Хорошо, потому что закрывает REQ-SEC-001, REQ-SEC-003, REQ-SEC-004 готовыми модулями.
* Хорошо, потому что знакомо большинству Java-разработчиков на рынке.
* Нейтрально, потому что время старта выше, чем у Quarkus.
* Плохо, потому что объём автоконфигурации требует внимания при отладке.

### Quarkus

* Хорошо, потому что быстрый старт и малое потребление памяти.
* Нейтрально, потому что экосистема безопасности и почты меньше.
* Плохо, потому что у команды меньше опыта, а junior-разработчику сложнее найти примеры.

### Jakarta EE (WildFly)

* Хорошо, потому что стандарт платформы.
* Плохо, потому что требуется сервер приложений; развёртывание в Docker сложнее (REQ-QUAL-006).
* Плохо, потому что для почты и сессий всё равно нужна дополнительная настройка.

## Дополнительная информация

Связанные требования: REQ-SEC-001…005, REQ-NOT-001, REQ-NOT-002, REQ-SEC-002, REQ-QUAL-006. Связанные решения: ADR-0002, ADR-0004, ADR-0005. Пересмотреть при изменении требований к нагрузке (REQ-PERF-002) или при переносе на нативную сборку.
