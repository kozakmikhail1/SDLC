# Клиентская часть — React SPA на Vite

## Контекст и постановка задачи

Ограничение 2.3 SRS фиксирует React для интерфейса (REQ-SEC-002). Нужно выбрать инструмент сборки и структуру клиентской части, чтобы её можно было запускать локально и собирать в Docker-образ (REQ-QUAL-006) и чтобы junior-разработчик мог работать с ней самостоятельно.

Вопрос: какой инструмент сборки выбрать для React SPA, чтобы сборка была быстрой, а конфигурация минимальной?

## Драйверы решения

* Скорость сборки и запуска для разработки — важно для junior (итерации 1–4).
* Поддерживаемость инструмента — REQ-QUAL-004 (актуальные браузеры).
* Минимальная конфигурация.

## Рассмотренные варианты

* Create React App
* Vite
* Next.js

## Итог решения

Выбранный вариант: «Vite», потому что Create React App официально устарел и не получает обновлений, Next.js добавляет серверную часть, которой в архитектуре нет (сервер уже Spring Boot), а Vite даёт быструю сборку и минимальную конфигурацию для SPA.

### Последствия

* Хорошо, потому что сборка и запуск в режиме разработки занимают секунды.
* Хорошо, потому что результат сборки — статические файлы, которые раздаёт nginx в Docker-контейнере web.
* Плохо, потому что часть туториалов в сети написана для Create React App; junior нужно предупредить.

### Подтверждение

* Сборка `npm run build` проходит в CI без ошибок.
* Проверка адаптивности REQ-UI-004 на ширине 360 px.

## Плюсы и минусы вариантов

### Vite

* Хорошо, потому что быстрый запуск и горячая перезагрузка.
* Хорошо, потому что минимальная конфигурация.
* Нейтрально, потому что требует дополнительной настройки маршрутизации для SPA.

### Create React App

* Хорошо, потому что знакома многим разработчикам.
* Плохо, потому что проект не поддерживается и медленнее.

### Next.js

* Хорошо, потому что встроенный серверный рендеринг.
* Плохо, потому что добавляет второй сервер, который не нужен архитектуре.

## Дополнительная информация

Связанные требования: REQ-SEC-002, REQ-UI-004, REQ-QUAL-004, REQ-QUAL-006. Связанные решения: ADR-0001.
